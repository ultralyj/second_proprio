# 论文阅读正文模板

以下字段按实际论文填写；单位、数值和公式以原文为准。一级标题用原文题目，
中文简称可置于括号内。保留六段阅读顺序，不复制这里的填写说明。

```markdown
# 原文题目

**作者与单位**：作者甲、作者乙（原文明确的单位）；作者丙（另一单位）。
**arXiv**：[编号v版本](原文链接)
**时间**：YYYY-MM-DD HH:MM:SS UTC

## 中文摘要

完整翻译原摘要；保留技术条件、作者结论、所有主要数值和限定词。

## Key insight

解释方法最关键的设计及其作用；明确区分作者贡献主张和解读判断。

## 方法管线

Mermaid 理解图，标清数据、模型、优化和实际执行之间的关系。

## 方法详解

围绕实际组件组织小节，在对应位置放本地原图、原图注要点、关键公式及符号解释。
公式与实验结论引用原文的章节/公式/表号。不要把全部原图集中到末尾才开始讲。

## 实验

少量关键结果、评价设置和局限。不要用长审计列表代替结果，也不要删除影响结论的
样本数、成功阈值、统计口径或未解决的原文冲突。

## 附录：补充材料

必要的详细实验、补充图、复现线索和局限；没有额外内容时省略。
```

方法管线应使用实际的 `mermaid` 代码围栏，图像使用 `figures/…` 相对路径。
若原文没有可核实的作者单位，直接标明缺失；不得用邮箱域名、作者姓名或研究主题
推断归属。`preparation.json` 中的署名片段是查证线索，不代表 HTML 作者—单位
对应关系已经可靠解析。

`review.json` 保留 `reason`、`sources`、`affiliation_evidence`、`coverage` 等适用字段。
`affiliation_evidence` 应说明原文定位和已核实的对应关系，或明确尚未核实；机构证据
不足不应被正文中的肯定表述掩盖。结果状态沿用技能验收规则。
