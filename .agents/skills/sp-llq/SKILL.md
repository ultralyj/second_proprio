# 关心 llq

读取项目配置的 `relationship`、`schedules.care` 与时区。当前基准为 2026-10-29 是第 973 天；计算公式为 `973 + (本地日期 - 2026-10-29).days`。配置是唯一基准，不再从今天反推一个未经确认的纪念日。

## 展示和记录

- 展示本地日期、在一起的第几天，以及一个温和具体的关心建议，例如认真听她分享当天发生的事。
- 心情指数范围为 1–5，只采用用户填写的信息；今天未填写则显示“待填写”。不根据沉默、提醒次数或旧分数估算她当天的真实心情。
- 当日结构化记录为 `private/relationship/YYYY-MM-DD.json`，字段为 `mood`（1–5 或 null）、`note`、`actions`（文字数组）。保留已有备注和行动，新增行动追加到数组；日期不明确时不要把旧记录改到今天。
- 对应可读输出为 `private/relationship/YYYY-MM-DD.md`。这是 JSON 的展示视图，用户记录以 JSON 为准；手动编辑 MD 时先将新增用户信息合并回记录，避免下次渲染丢失。

定时提醒由项目执行器负责，默认模板即可，不需要为每次提醒额外调用模型。遵循配置中的时间及通知设置，不另建重复提醒。恢复在线时显示当前适用提醒，不把错过的每条提醒一次性弹出。

提醒只面向用户；给出关心建议不代表已经关心过，只有用户明确记录的行动才放在“今天已经做过”。不向 llq 发消息，不收集她的聊天或其他数据。私人记录不进入公共学术内容。

## 完成输出

交互时简洁显示“第 N 天／心情指数／今天一个关心行动”；后台调用按要求返回真实输出路径与完成状态。无当天心情数据也能完成提醒，但不得填一个猜测分数。
