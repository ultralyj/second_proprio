# second proprio Mac App 使用说明

本版面向 Apple Silicon Mac，使用现有仓库
`/Users/ultralyj/repo/second-proprio`。论文、课程、配置、队列和私密记录继续保存在
原目录；App 是这些数据的阅读、编辑和管理入口。

本文描述已实现的操作和部署机制。文末列出的原生验收项目需要在实际安装的
`.app` 中逐项验证；本文不代表已经完成安装、登录重启或通知实机验收。

## 首次打开与后台

1. 打开已打包的 `second proprio.app`。界面未连接后台时会显示连接错误，点击
   “启动并连接后台”连接或安装用户级后台服务。
2. 如果提示旧后台或 Codex 子进程仍在工作，先等待其结束，再次启动。迁移过程会
   检查旧执行器锁和子进程，避免两套调度器同时处理原目录。
3. 在“设置”中确认课题、日程、时区和 Codex CLI 路径，并检查登录状态。
4. 在“任务”中查看已登记任务；需要马上处理时使用对应模块的运行按钮。

后台由 launchd 托管。窗口关闭后隐藏到菜单栏；菜单栏的
“退出界面（后台继续）”只结束界面。再次打开 App 可以接回原来的任务。

“暂停 AI 任务”让当前任务继续，暂不领取后续论文、课程和复盘任务；关心提醒
继续按配置执行。“设置 → 停止后台”会明确请求取消当前任务、等待退出，再停用
服务。草稿和已保存内容保留。再次打开 App 后可以手动启动。

## 页面与日常操作

| 页面 | 操作 |
| --- | --- |
| 今日 | 查看新增内容、需要处理的任务、关心状态和通知记录，点击进入对应页面。 |
| 论文 | 按标题或 arXiv ID 搜索，按课题、状态和日期筛选；查看解读、插图和版本信息。 |
| 课程 | 选择章节，阅读正文，展开笔记或反馈；打开示例源码，主动勾选已学完。 |
| 复盘 | 阅读或编辑按日期归档的复盘，导入 ChatGPT JSON，或补充某一天的文字记录。 |
| 关心 | 选择日期，填写 1–5 分心情、备注及行动，修改或清空后点击“保存记录”。 |
| 任务 | 查看排队、运行、等待来源、等待采纳、失败和历史任务，单独取消或重试。 |
| 设置 | 调整业务配置、外观、通知和后台启动策略，查看数据目录和服务器同步状态。 |

论文原始 PDF、课程 `.py` 示例和数据目录通过系统应用或 Finder 打开。内容列表
只读取现有文件，不会因为打开页面而生成课程或创建笔记。

### 课程笔记与反馈

在章节右侧笔记区记录答案、疑问和理解，正式保存后才成为下一次反馈的输入。
保存笔记本身不调用模型。可以等待每日课程任务处理，或者点击“获取反馈”，
只处理所选章节，不生成下一节，也不使用当天新增课程额度。

“已生成”和“已学完”是两种独立状态。只有主动勾选才表示已学完；单独改变
完成勾选不触发反馈。没有新笔记时课程仍可继续，系统不会据此认定已经掌握。
反馈保存在独立文件，模型不能改写已经存在的个人笔记。

课程示例的 `.py` 文件是代码来源。正文预览会从关联源码更新代码块；需要修改
算法时打开源码文件编辑，不能单独把正文中的对应代码块改成另一份实现。

### 复盘来源

“导入记录”使用系统文件选择器导入 ChatGPT 导出 JSON 或已支持的记录快照。
“补充记录”可指定日期并写下当天活动。导入成功后，相应日期处于“等待来源”
的任务会重新排队；也可以通过模块运行按钮提交任务。

复盘会记录来源及覆盖范围。Codex CLI 的 ChatGPT 登录状态不等于能够读取聊天
历史；没有当天来源时显示“请告诉我今天的记录在哪里。”，不会编造完成事项。
人工补充记录也是来源，应区分已经完成、讨论过和计划中的事情。

### 关心记录

默认天数计算为 `973 + 当前日期与 2026-10-29 的天数差`。因此基准日为第 973 天，
次日为第 974 天。名称和基准可在设置调整。

心情默认“待填写”，不会猜测或继承昨日分数。清空心情、清除备注、删除行动后
需要点击“保存记录”才会生效；三个字段都清空后对应自填记录会移除。日期选择器
和最近记录可用于修正历史。系统不会向 llq 自动发送消息。

## 配置保存

设置分为论文、课程、复盘、关心、通用和高级参数。高级项包含 CLI 路径、模型
覆盖、超时、失败重试及服务器连接。模型留空时继承 Codex 自身配置。

修改后必须点击“保存”。表单和命令行使用同一 JSON Schema 校验；非法配置保留
草稿并显示错误，不替换有效配置。配置文件被外部修改时也会检查版本，避免覆盖。
保存结果会区分本机保存、后续任务生效及服务器同步状态。服务器未启用或不可达
不影响本机使用。

正在运行的任务使用启动时的配置快照。日程修改只重新计算尚未开始的自动任务，
已完成成果不会因此重做。数据目录在本版只能查看和打开，不能在运行中搬迁。

## 正文编辑、草稿与候选

阅读页可切换编辑、预览和双栏预览。编辑中的文字自动保存为草稿；“保存”或
`⌘S` 才提交正文并创建修订。`⌘F` 查找当前正文，`⌘,` 打开设置。

如果正文被外部编辑器或后台更新，正式保存会阻止覆盖并显示差异。草稿保留，
可以比较后再合并。历史中的“恢复此版本”创建新修订，不删除已有历史。

AI 在独立工作区生成。通过原有内容验收后，新文档可自动发布；已有正文一旦被
人工修改，或生成期间文件发生变化，就产生“等待采纳”候选。接入前缺少可信
历史基线的旧文件也保守地作为候选处理。

打开候选可比较当前正文和候选正文，查看一起发布的源码、目录或元数据文件。
可以直接采纳、修改候选正文后采纳，或放弃。采纳会重新检查整组文件的版本；
任一关联文件变化都不会静默覆盖。论文的 arXiv 版本与这些本地修订分开记录。

放弃候选保留当前正文和生成草稿。相同输入不会在自动任务中反复生成；手动提交
新任务视为明确请求重新生成。候选是一次生成的关联文件组，采纳会一起发布其
正文、示例和状态元数据。

## 任务、恢复与通知

“立即运行”只登记任务并迅速返回。任务中心展示实际阶段、正在处理的对象、
耗时、最近事件和错误；没有可靠总量时不显示虚构百分比。

取消运行中的任务先显示“取消中”，确认进程退出后变为“已取消”。取消不消耗
失败预算，不自动重启，保留草稿。单项重试只重试所选失败、取消或等待来源的
任务，重新给予失败预算。普通自动重试留在任务中心；登录失效、失败耗尽和
缺少来源会成为需要处理的提醒。

任务中断后保留独立工作区和发布清单。发布先处理正文与源码，再处理完成状态；
只有发布完成后才提交成果计数。恢复检查若遇到外部文件变化会停止覆盖，保留
事务和错误供处理。不要在运行中手动删除 `.state` 中的草稿、发布清单或数据库。

电脑关机时不会生成内容或实时通知。恢复后补查未处理论文；课程每个实际执行日
最多新增一节；过期关心提醒合并为当天提醒，不补弹历史提醒。

系统通知通过 App 的无窗口入口投递，界面退出后仍可工作。通知请求被系统接受
不代表用户已经看见；系统权限、专注模式等会影响展示。通知失败和待处理事项
仍可在 App 中查看。通知权限在 macOS 系统设置中管理。

## 本机数据与隐私边界

- 配置在 `config/`，SQLite 队列、日志、编辑历史、草稿和发布事务在配置指定的
  状态目录，默认 `.state/`。
- 课程和论文正文仍在 `courses/`、`papers/`。原始聊天、复盘、心情、课程笔记和
  反馈在配置指定的私密目录，默认 `private/`，默认不纳入 Git。
- 论文生成工作区不复制私人记录；课程复制必要笔记和反馈，单节反馈只带该节
  私人材料；复盘只带指定日期的来源及该日正文。
- 这些内容不上传 Ubuntu 服务器。生成时必要资料会作为输入交给本机 Codex CLI，
  沿用现有登录及模型设置；本版没有增加另一个付费 API 接入。
- React 通过 Tauri 的固定接口连接 Unix Socket，不开放本机 HTTP 服务，也不能
  从正文直接执行 shell。外部论文、聊天和附件中的文字只是分析材料。

## 构建、迁移与回退

开发构建从仓库根目录执行 `uv run python packaging/build_app.py`，需要项目开发
依赖、Node/npm、Rust 及 macOS 构建工具。脚本构建独立 Python 运行时和 Tauri App，
产物为 `desktop/src-tauri/target/release/bundle/macos/second proprio.app`，使用本机
临时签名。此构建方式不包含 App Store 发布、公证或自动更新。

首次启动后台会把完整运行时复制到
`~/Library/Application Support/second-proprio/runtime/<版本与构建指纹>/`，后台不依赖
开发用 `.venv`。用户登录项为
`~/Library/LaunchAgents/com.second-proprio.desktop-service.plist`。运行时信息保存在
Application Support 下的 `runtime.json`，其中包含最近一次迁移备份路径。

切换前会备份配置、Schema、SQLite 队列和旧登录项到
`.state/migration-backups/<时间>/`。旧登录项停止并移走后才加载新服务。新服务启动
失败时会尝试恢复之前的登录项，同时保留诊断和队列；界面会显示真实失败结果。

需要人工回退时，先在 App 中取消当前任务并停止后台，确认没有写入任务后，
由维护者使用 `desktop_deployment.rollback_service(root, backup, target)` 恢复最近
备份的旧服务定义；`target` 是上述新登录项路径。该操作仅恢复服务入口，不会用
旧 SQLite 快照覆盖新任务历史。若要恢复数据库或配置，必须先另存当前副本并
核对迁移后新增记录，不应直接覆盖。回退后暂不点击 App 的“启动后台”，以免
再次切换。代码入口见 `src/second_proprio/desktop_deployment.py`。

排查后台问题优先查看任务详情，以及 `.state/logs/desktop.stderr.log`、
`.state/logs/desktop.stdout.log`。单次执行日志和结果位于
`.state/desktop-runs/<运行 ID>/`，草稿工作区位于 `.state/draft-runs/`。
日志可能含来源路径或任务内容，不要直接公开上传。
